(Screenshot of Digital Paani live UI attached)
We've taken inspiration from the design you created and came up with something of our own. I've attached the screenshot of our design which is live. First, create the design accordingly and then we'll continue working on it.

We're going to create something known as "Set-points" - let me give you context on the same. Currently, the set points are configured on the HMI which is available on-site and can be overridden by the operator/supervisor available on-site. We're going to introduce that control in our software.

This set point configuration will be done in levels:
* Parent Level config - where set point can be activated and which equipment(s) does it link to. The set point will have a threshold as well (min and max - along with a safe range)
* Child level config - where the actual set point is set.

Set point controls will affect the equipment functioning and their attributes. When I say attributes, I mean their ON/OFF status based on time and their VFD output (RPM, frequency and current). This logic on which equipment attributes are set is already fed into the PLC through the automation logic. So technically, we're giving the capability to overwrite set points only without touching the logic.

Please figure out where the parent level config will exist. As far as the child level config is concerned, let's do two things:
1. The equipment drawer that is shown in the screenshot attached (also take context from the design that you created) - let's introduce set point edits.
2. Create a new screen where all available set points are shown to the user and the capability to overwrite them.

Here are the following places/purposes where set points can be introduced:
Level: will trigger the start/stop of equipment(s) [collection tank level → transfer pump]
DO: will trigger the on/off and also VFD output (RPM, frequency & current) of blowers.
Differential Pressure: triggers a backwash (on/off of valves).
Differential Pressure (calculated): same.
pH: triggers on/off of dosing pumps.
FRC: triggers on/off of dosing pumps.
ORP: triggers on/off of dosing pumps.
Flow: VFD output of pumps.
Time: backwash duration, etc.

Let's first create the user interface and make it visually attractive. Also, include a notice to the user at the time of editing a set point notifying him about the upcoming behavior change of equipment(s).

Once that is done, let's design the parent level config and ship it to https://mihirsethidp.github.io/RemoteControlNotAtAllOfficial/configuration.

[37] Lock to 5 set-point types
──────────────────────────────────────────────────────────────
As per the new requirements, there are only 5 types of set points.

1. DO (Dissolved Oxygen)
2. PT (Pressure Transmitter)
3. LT (Level Transmitter for tanks for Transfer Pump Operating Range of Intake and Outlet Tank)
4. Flow rate (for permeate pumps or flow-based equipment)
5. Switchover Time.

Also, take into consideration the following requirements:

1. The real-time value (live PLC tag) must be shown. This is the currently set set point which is static.
2. A Setpoint Control popup must open with:
* Slider UI (recommended)
* Slider min/max = configured safe limits
* Slider initial position = current value
3. Numeric entry must also be supported for precision.
4. The UI must clearly show:
* Current real-time value
* Allowed safe range (min/max)
* Units (mg/L, %, m, m³/hr, LPM, bar, etc.)

On the client view,
1. Setpoint changes must trigger warnings when the value is beyond defined safe range.
2. A popup warning must appear if a user-selected value enters the warning region.
3. Operators may override and forcefully apply the setpoint despite warnings. The system only warns; it does not block setpoint changes.

When the user adjusts a setpoint:
* Validate the input against configured min/max limits.
* Show a soft-warning popup if the value entered is in the caution region.
* Allow the operator to override and proceed.
* Display success/failure status.
* Log the update including: Old value → New value, User ID, Timestamp

Per-type configuration popups (DO, LT, Flow/Permeate, PT, Switchover Time) — full context as per Phase 2 doc.

[39] Three feedback items + revamp ideas (Unit Processes)
──────────────────────────────────────────────────────────────

Let's work on a revamp of this feature, I have new ideas:
1. Let's get rid of the set point configuration screen. The set points are configured on a unit process. We have an algo in our system which will identify and fetch all the unit processes (set of multiple equipments contributing/performing one process) for the plant. So, the configuration can be done from the main visualization screen itself. There is one place where we configure the visualization of the plant and there is the client view - where the client can view the configured visualization.
2. On the configuration side - since we will fetch unit processes - set points can be configured for each unit process and one unit process can have multiple set points. The side drawer (which currently opens after clicking on Set Points on the client view) - when you duplicate it on the configuration side - it will enlist all unit processes which are identified by the algo - each unit process will have the option to add/delete set points. Also, since the algo may not fetch the exact equipments - there will be a manual override as well - the user can add/delete equipments from a unit process.
3. On the client side, the Set Points drawer will be renamed to "Unit Processes" - it will enlist all the unit processes from the plant and all the set points that are configured on that unit process will be enlisted with the option to edit them - as they can be edited even now on the current prototype.
4. There will be a notification configuration as well for each set point change and the notification configuration will be for users and their preferred channels to notify them of a set point change.
5. In no case, the set point change will fail the fallback logic installed on the PLC logic so the user must be notified of it.
6. Introduce a "processing" screen after the set point change request is sent to the server.
7. The warning/safety screen remains intact, after the set point change is submitted. The "Processing" screen comes after.
8. Introduce an edit button on set points - the edit button then lets the user edit values in a progressive disclosure.
